## v0.6.0 - 2026-09-22
### Added
* Added explain-cypher and profile-cypher tools for query tuning: explain-cypher returns the query plan for a Cypher statement (read or write) without executing it, and profile-cypher executes a statement and returns both the results and a profiled plan with runtime statistics (dbHits, rows, time, page cache hit ratio per operator). Also added five schema-management tools — list-constraints-and-indexes for structured discovery, and create-constraint/drop-constraint/create-index/drop-index for managing uniqueness, key, and property-existence constraints and range/text/point/lookup indexes — all driven by structured fields rather than raw Cypher, so an agent never needs to read or write Cypher DDL syntax to use them. Vector and fulltext indexes are intentionally out of scope for create-index.
* Added a search category with five tools for vector and full-text search: vector-search and fulltext-search run approximate-nearest-neighbor and Lucene-backed queries against existing VECTOR/FULLTEXT indexes via structured fields (no Cypher required), auto-detecting the target node label or relationship type from the index itself; create-vector-index and create-fulltext-index create those indexes, filling the gap create-index intentionally left open; set-vector-property writes an embedding onto a node or relationship via db.create.setNodeVectorProperty/setRelationshipVectorProperty. The category requires a server on calendar 2026.09.0+ or classic 5.27-aura+ (needed for the SEARCH clause's full-text support) and is automatically excluded from tools/list on older servers rather than failing at call time.
### Fixed
* write-cypher no longer silently mishandles EXPLAIN- or PROFILE-prefixed queries: an EXPLAIN prefix previously returned an empty, misleadingly successful-looking result (EXPLAIN produces no rows), and a PROFILE prefix executed the query but silently discarded the resulting profiling data. Both are now rejected with a message pointing at the new explain-cypher and profile-cypher tools.
* The TOOL_USED analytics event's vector/fulltext-usage flags (vectorSearch, vectorPropertySet, fullTextSearch) only covered read-cypher/write-cypher (via string-detection on the raw query, the only way to do this before the search category existed) plus a hardcoded case for vector-search. fulltext-search and set-vector-property now tag their own flag unconditionally; explain-cypher and profile-cypher go through the same string-detection as read-cypher/write-cypher, since they carry the same raw query argument. profile-cypher also now triggers the GDS project-created/dropped events, since it executes for real like write-cypher; explain-cypher deliberately does not, since EXPLAIN never executes.
