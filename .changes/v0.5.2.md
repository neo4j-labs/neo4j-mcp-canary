## v0.5.2 - 2026-09-22
### Changed
* Rewrote the MCP server's `instructions` field (shown once to connecting clients) to describe the tool-discovery workflow instead of naming a fixed set of tools. The previous text hardcoded tool names and had already drifted — it never mentioned give-feedback, and claimed get-schema surfaces full-text/vector indexes, which it doesn't (get-schema runs APOC's `apoc.meta.schema`, which has no index field). The new text keeps get-schema/read-cypher/write-cypher named as the foundational workflow, points out that full-text/vector indexes can still be queried directly via `db.index.fulltext.queryNodes()`/`queryRelationships()` and `db.index.vector.queryNodes()`/`queryRelationships()` even though get-schema won't list them, and tells clients to check the live tool list for anything else rather than assuming a fixed set.
### Fixed
* Removed the `vectorIndex`/`fullTextIndex` properties from the `TOOL_USED` analytics event. They were populated by parsing an `indexes` field out of get-schema's JSON response, but get-schema switched to APOC's `apoc.meta.schema` (which has no such field) without updating this parsing code, so both properties had silently reported zero on every call since that change. `vectorSearch`, `vectorPropertySet`, and `fullTextSearch` (detected directly from the Cypher query text, unaffected by that change) are still reported.
