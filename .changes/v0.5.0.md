## v0.5.0 - 2026-09-21
### Added
* Tools now belong to a mandatory category (cypher, gds, feedback) and carry a label (their existing MCP title annotation), exposed as metadata for tool selection. Added NEO4J_MCP_ENABLED_TOOLS and NEO4J_MCP_ENABLED_TOOL_CATEGORIES to statically narrow the registered tool set by name or category at startup. In HTTP mode, a client can further narrow the tool set for a single request via the X-MCP-Tools and X-MCP-Tool-Categories headers (names configurable via NEO4J_MCP_HTTP_TOOLS_HEADER_NAME / NEO4J_MCP_HTTP_TOOL_CATEGORIES_HEADER_NAME); a selection can only narrow what NEO4J_READ_ONLY, GDS availability, or the static selection already allow, never widen it.
### Changed
* Introduced an internal MCP SDK abstraction layer (internal/mcpsdk) and migrated the server and all tools from the community mark3labs/mcp-go SDK to the official modelcontextprotocol/go-sdk. Tool specs, handlers, request/result types, and the server's stdio/HTTP transports and tool-call/handshake hooks now go through this internal wrapper instead of importing an MCP SDK directly, so a future breaking change in the MCP spec or its SDKs is absorbed in one package instead of rippling through every tool and every test tier. This is an internal dependency change with no intended effect on tool behavior, schemas, or the wire protocol.
### Fixed
* Lowered the Query API version gate's classic-Aura floor (CheckMinimumVersion) from 5.27-aura to 5.26-aura. Classic-versioned Aura releases at or above 5.26-aura are now accepted; the "-aura" suffix is still required — a bare classic version with no suffix is rejected regardless of how new it is, since self-managed classic servers predate the typed-JSON media type version this server's Query API client depends on and can't actually serve Query API requests successfully.
