## v0.9.1 - 2026-10-20
### Changed
* A custom tool parameter can now be `required: true` and also have a `default`. The statement always receives a value, but the model is not told it must supply one: the parameter is left out of the tool's required list and the default is advertised in its schema. Previously this combination was rejected.
### Fixed
* The graph, traversal and patterns tools no longer fail silently. An update-node, delete-node, update-relationship or delete-relationship call that matches nothing (for example a wrong or mistyped id) now returns `performed: false` with a message saying nothing matched, instead of `performed: true` with `message: null`. A `dryRun` that matches nothing now returns `matched: 0` and an explanation instead of an empty result. These tools also reject an argument they do not declare, and list the valid ones, instead of ignoring it and returning a result that quietly lacks what was asked for (for example `neighborProperties` instead of `nodeProperties`). find-shortest-path and find-all-paths now say in their descriptions that nodes carry only id and labels unless `nodeProperties` is passed.
* Custom tool validation no longer mistakes text inside a string literal, quoted identifier or comment for a Cypher parameter. A statement such as `RETURN '$example'` or one with `// uses $example` was rejected as referencing an undeclared parameter, and a declared parameter mentioned only in a comment counted as used. A statement that is only comments is now reported as empty.
* Command-line flags now accept the standard `--name=value` form (`--config-file=config.yaml`, `--neo4j-uri=bolt://localhost:7687`, `--validate-config=true`) as well as `--name value`. Previously the `=` form was rejected as an unknown argument.
