## v0.4.0 - 2026-08-19
### Added
* Add an optional TOON (Token-Oriented Object Notation) tool response format, alongside the existing default JSON, via NEO4J_OUTPUT_FORMAT / --neo4j-output-format. TOON reduces LLM token usage versus JSON for the tabular row shapes read-cypher, write-cypher, get-schema, and list-gds-procedures return.
* Include the active NEO4J_OUTPUT_FORMAT (json or toon) as an output_format property on the TOOL_USED Mixpanel event.

## v0.3.1 - 2026-08-19
### Added
* Support an optional JSON/YAML config file as a new lowest-priority configuration source (below environment variables, below CLI flags) via --config-file / NEO4J_CONFIG_FILE. As part of this refactor, the four NEO4J_HTTP_ALLOW_UNAUTHENTICATED_* flags now consistently default to true when given an invalid value from any source (previously a malformed CLI value fell back to false while a malformed env var fell back to true).

## v0.3.0 - 2026-08-19
### Added
* CLI flags for all operational controls, matching the existing environment-variable surface. Previously the byte cap (`NEO4J_CYPHER_MAX_BYTES`), row cap (`NEO4J_CYPHER_MAX_ROWS`), timeout (`NEO4J_CYPHER_TIMEOUT`), and estimate guard (`NEO4J_CYPHER_MAX_ESTIMATED_ROWS`) were only configurable via environment variables and were absent from `--help` output, making them undiscoverable for operators tuning a canary deployment. The new flags are `--neo4j-cypher-max-rows`, `--neo4j-cypher-max-bytes`, `--neo4j-cypher-timeout`, and `--neo4j-cypher-max-estimated-rows`, each with env-var precedence semantics matching the existing flag pattern. The `--neo4j-schema-sample-size` flag, which previously parsed the value but silently discarded it (it was never threaded through `CLIOverrides` to `LoadConfig`), is now functional. All five flags are documented in the `--help` output in both the Options and Optional Environment Variables sections.
* Added a "Building from Source" section to the README covering local builds via Task/go build, cross-compiling for macOS and Linux (amd64/arm64) with CGO_ENABLED=0, stamping a version via -ldflags, and a pointer to GoReleaser for official multi-platform release archives.
* Added a give-feedback tool that lets an agent/LLM submit free-text feedback about the MCP server itself (positive or negative) — for feedback on the server's tools, behaviour, or documentation, not for reporting Cypher/database errors. Feedback is a single string argument capped at 300 characters, enforced both in the advertised tool schema (maxLength) and by the handler. Feedback is sent as a new FEEDBACK Mixpanel event alongside the server's other telemetry, so it is only recorded when telemetry is enabled — the tool call itself always succeeds regardless.
* The MCP_STARTUP telemetry event now includes a connection_mode property ("bolt" or "query_api") indicating which wire protocol the server is using to talk to Neo4j, derived from the scheme of NEO4J_URI. This lets us distinguish Query API adoption from Bolt in the startup event, alongside the existing transport_mode property (which describes the MCP client-facing transport, not the Neo4j connection).
* The server can now connect to Neo4j over the HTTP-based Query API instead of Bolt, auto-detected from the scheme of NEO4J_URI — http:// or https:// selects the Query API, everything else (bolt://, neo4j://, and their +s/+ssc variants) keeps using the existing Bolt driver, with no new configuration flag required. Query API mode requires Neo4j 2026.07 or newer (calendar-versioned releases) or 5.27-aura or newer (classic-versioned Aura releases only) — one release past the Query API's own general availability (2026.06), since read-cypher's write-query rejection depends on the queryType field Neo4j only introduced in 2026.07; the server checks the connected instance's reported version at startup via an unauthenticated GET to the base URI and refuses to start against an older or unrecognized version. Both STDIO and HTTP transport modes are supported, including HTTP mode's per-request Basic/Bearer credential impersonation. read-cypher, write-cypher, get-schema, and the other Cypher-executing tools behave identically over either wire protocol, including row/byte truncation caps, the EXPLAIN-based write-query rejection in read-cypher, and the planner row-estimate guard. One known limitation: Neo4j's Date/Time/LocalTime/LocalDateTime/OffsetDateTime Cypher types are collapsed to a single decoded shape by the underlying Query API client library, so the JSON rendering of these temporal types in Query API mode is a best-effort approximation rather than an exact match to the Bolt path for every case.
### Changed
* **Breaking:** read-cypher and write-cypher JSON responses now wrap Neo4j driver types in camelCase JSON shapes instead of leaking Go struct field names through reflection-based serialisation. Previously the `record.AsMap()` output was marshalled directly, producing `{"Id":..., "ElementId":..., "Labels":..., "Props":...}` for nodes (PascalCase Go field names) and `{}` for `dbtype.Date` values (empty object because the struct's fields are unexported). The new wrappers emit `{"elementId":..., "labels":..., "properties":...}` for nodes and relationships (deprecated numeric `id` / `startId` / `endId` are dropped; `elementId` and `startElementId` / `endElementId` are the only identifiers surfaced), `{"nodes":..., "relationships":...}` for paths, `{"x":..., "y":..., "srid":...}` for `Point2D` / `Point3D` (matching Cypher's `point()` output), and ISO 8601 strings for `Date` / `LocalTime` / `LocalDateTime` / `Time` / `Duration`. Clients that parsed the old PascalCase shape must update their field access — notably any code reading `.Id` / `.ElementId` / `.Labels` / `.Props` on nodes, or expecting dates as an empty object. The new shape aligns with the Python Neo4j MCP server output, Cypher conventions, and Bolt-protocol naming.
* get-schema now uses APOC's `apoc.meta.schema` procedure to retrieve schema information, matching the upstream neo4j/mcp server. This replaces the `db.schema.nodeTypeProperties` / `db.schema.relTypeProperties` primary path, the per-label / per-type sampling fallback, the `SHOW CONSTRAINTS` required-property surfacing, and the completeness heuristic that cross-checked the indexes array against the nodes/relationships arrays. APOC is now a hard requirement for the tool. The response shape changes to the flat `[{key, value: {type, properties, relationships}}]` list APOC returns. The `NEO4J_SCHEMA_TIMEOUT` environment variable and `--neo4j-schema-timeout` CLI flag are removed along with the fallback — APOC's own `sample` parameter (still configurable via `NEO4J_SCHEMA_SAMPLE_SIZE` / `--neo4j-schema-sample-size`) handles bounded sampling on large graphs.
### Fixed
* read-cypher and write-cypher now surface query timeouts with a classified, actionable error instead of the raw driver passthrough. The previous behaviour returned "ConnectivityError: context deadline exceeded" when a query outran `NEO4J_CYPHER_TIMEOUT`, which sent operators hunting network/DNS issues before realising the query itself was the cause. The new error names the configured timeout value and includes remediation guidance tailored to each tool — bounding variable-length patterns, adding WHERE filters, or using LIMIT for read-cypher; reducing batch size, narrowing the MATCH, or using apoc.periodic.iterate for write-cypher. Caller cancellation (as distinct from timeout) now surfaces as a concise "cancelled" message without a remediation hint. Wrapped context errors (for example the driver's ConnectivityError enclosing context.DeadlineExceeded) are unwrapped via errors.Is so classification still fires through the driver's wrapping layer.
* read-cypher and write-cypher no longer leak the internal `EXPLAIN ` prefix through driver error messages. Query classification prepends `EXPLAIN ` to the user's query to detect read/write intent, and when the driver returned a syntax error it echoed the prefixed query text, cited column and offset positions against the wrapped version, and drew a caret aligned to those positions — referencing a keyword the user never typed. A new `sanitizeExplainPrefix` pass now strips `"EXPLAIN ` from the quoted echo, shifts `column N` and `offset: N` references by 8 (the prefix length), and dedents the caret line by the same amount, producing an error that reads as if the user's original query had been sent directly. The sanitiser preserves the error chain via a custom wrapper type, so `errors.Is` and `errors.As` continue to unwrap to the underlying driver error for upstream classification. Errors that don't reference the wrapped query pass through unchanged.
